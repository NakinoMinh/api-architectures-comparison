01 · Bức tranh tổng quan

Bốn cách tổ chức giao tiếp, bốn ưu tiên khác nhau

Không có kiến trúc nào tốt nhất trong mọi bối cảnh. Điểm xuất phát là hiểu mô hình giao tiếp, ràng buộc hợp đồng và nhu cầu của hệ thống. Nhấn vào một thẻ để xem giải thích chi tiết.

Messaging protocol

SOAP là gì?

SOAP (Simple Object Access Protocol) là một giao thức nhắn tin để trao đổi thông tin có cấu trúc giữa các hệ thống phân tán.

    03 · Lựa chọn kiến trúc
    
      
    REST cho hệ thống quản lý sinh viên
    
      
    Chọn REST làm API chính cho cổng thông tin sinh viên, ứng dụng giảng viên và bộ phận quản trị.
    
      
    
        
    
          
    Recommended primary API
    
          
    REST
    API
    
          
    Một lựa chọn cân bằng giữa tính dễ dùng, tương thích đa nền tảng và chi phí vận hành cho luồng CRUD của nhà trường.
    
          
    HTTP + JSONDễ tiếp cận cho web & mobile
    Resource modelKhớp với students, courses, enrollments
    
        
    
        
    
          
    Vì sao phù hợp?
    
          
    Hệ thống có các thực thể rõ ràng: sinh viên, môn học, lớp học phần, đăng ký và điểm. REST biểu diễn tự nhiên các thực thể đó thành tài nguyên và ánh xạ thao tác nghiệp vụ vào HTTP.
    
          
      
            
    • CRUD rõ ràng: GET /students, POST /enrollments, PATCH /students/{id} dễ đọc và nhất quán.
      • 
            
    • Phủ rộng client: Browser, mobile app và công cụ quản trị đều làm việc tốt với HTTP/JSON.
      • 
            
    • Dễ bảo trì: OpenAPI, logging, API gateway, caching và monitoring có hệ sinh thái rất trưởng thành.
      • 
            
    • Mở rộng hợp lý: Stateless request hỗ trợ scale ngang; ETag/Cache-Control có ích với catalogue môn học.
      • 
          
    
          
    Quyết định có điều kiện: REST là API chính cho client. Nếu sau này có báo cáo dashboard cần nhiều dữ liệu liên kết, có thể bổ sung GraphQL ở BFF; các dịch vụ nội bộ cần độ trễ thấp có thể giao tiếp gRPC. Đây là kiến trúc lai bổ sung, không phủ định lựa chọn REST.

    06 · Trải nghiệm trực tiếp
    
      
    Trình giả lập REST API tương tác
    
      
    Mô phỏng request từ Student Portal đến REST API bằng dữ liệu của các thành viên nhóm: thử các hồ sơ khác nhau và cơ chế ETag cache. Hoàn toàn chạy trong trình duyệt, không gửi dữ liệu ra bên ngoài.
